# Implementation Plan: Линза мест при выборе Поселенца

**Branch**: `001-settler-site-lens` | **Date**: 2026-10-28 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-settler-site-lens/spec.md`

## Summary

Когда игрок выделяет Поселенца, мод сразу показывает:
- окраску мест для города в 4 ступени относительно мест в радиусе 8 клеток;
- номера трёх лучших мест;
- полупрозрачную раскладку всех специализированных районов цивилизации, с Акведуком и Дамбой,
  вокруг лучшего места или места под курсором;
- в стандартной подсказке клетки — балл, слагаемые с причинами, диапазон неопределённости или
  причину отказа.

Технический подход:
- Всё считается заранее в фоне по кадрам, в главном контексте `InGame`.
- Расчёт идёт в два уровня:
  1. грубая оценка всех открытых мест;
  2. точная раскладка через DMT для мест рядом с Поселенцами.
- DMT подключается в своё Lua-состояние со слоем воображаемых меток (включая воображаемый центр
  города) и обёртками-исправлениями.
- Раскладку ищет свой метод ветвей и границ: верхняя оценка по задаче о назначениях, парные надбавки
  по конкретным клеткам, тёплый старт от соседнего места. Он доказывает оптимум или сообщает разрыв.
- Тройка лучших мест доказуема: уточняются только места, которые ещё могут её обогнать (R21).
- Обрабатываемые клетки выбираются точно с учётом еды и жилья (R22); прибрежные низины учитываются
  с поправкой на подъём моря (R23).
- В подсказке — разница с местом № 1 (R24), на карте — отметки обрабатываемых клеток (R25).
- Для разработки: тесты на снимках открытой части реальных карт (R26) и автосбор расхождений DMT
  с движком (R27).
- Код других модов не используется (принцип X); их идеи и наши улучшения — в R20.
- Неоткрытые клетки оцениваются ожидаемой ценностью по правилам генерации карты.
- Подсказка встраивается заменой `PlotToolTip` поверх Expansion2.

Подробности — в [research.md](research.md).

## Technical Context

**Language/Version**: Lua 5.1 (Havok Script в Civilization VI 1.0.12.x, macOS / Windows); XML для UI,
текстов и modinfo. Инструменты: Python 3 (выгрузка правил, клиент FireTuner).

**Primary Dependencies**: Civilization VI + Gathering Storm; Detailed Map Tacks (Workshop 2428969051,
версия 2024-01-17) — подключается в своё состояние, файлы не копируются.

**Storage**: нет. Данные живут в памяти главного контекста; в сохранение ничего не пишется.

**Testing**: автономные тесты на Lua 5.1.5 (`.tools/lua51`, hererocks) со своим раннером
`tests/run.lua` и поддельным миром из выгруженного `DebugGameplay.sqlite`. Проверка в игре по
[quickstart.md](quickstart.md); вывод через FireTuner.

**Target Platform**: Civilization VI на macOS (основная машина разработки), одиночная игра. Windows
поддерживается по устройству мода, но в функции 001 не проверяется.

**Project Type**: мод для игры: UI-контекст и модули логики.

**Performance Goals**:
- ответ при выделении ≤ 0,2 с (SC-001);
- места рядом с Поселенцами полностью готовы ≤ 10 с после начала хода; грубая оценка всей карты
  ≤ 60 с; раскладка места под курсором ≤ 2 с (SC-003).

**Constraints**:
- падение частоты кадров ≤ 10 %, нет кадров > 100 мс по вине мода (SC-002);
- квота работы за кадр — в операциях (принцип VII);
- детерминизм (принцип IV);
- только видимое игроку (принцип IX).

**Scale/Scope**:
- карта до Huge — около 10 000 клеток, из них открыто и законно обычно 500–3 000 мест;
- 9–12 районов в раскладке на 25–35 клетках;
- 30 мест рядом с каждым Поселенцем (оценка в R19).

## Порядок реализации

Определяет `/speckit-tasks`; здесь ориентир. Каждый шаг заканчивается проверкой.

1. **Этап 0 — каркас и проверки игры.** Modinfo, `SA_Main`, событие выбора Поселенца, вывод через
   FireTuner, замена подсказки с одной строкой. Закрыть все «[проверить в игре]» из research.
2. **Тестовая база.** Lua 5.1, раннер, выгрузка правил, поддельный мир, снимки реальных карт (R26).
3. **Уровень 1.** `SA_World`, `SA_Rules`, `SA_Candidates`, `SA_Prior`, `SA_Tiles` (еда, жильё, низины),
   `SA_Coarse`, `SA_Score`, `SA_Explain` (с разницей с № 1), `SA_Scheduler`; окраска, номера,
   отметки клеток, подсказка. Это истории 1, 2 и 4 без районов.
4. **Уровень 2.** `SA_DMT` с исправлениями, `SA_Layout`, `SA_Rank`, предпросмотр значков, Акведук
   и Дамба, автосбор расхождений (R27). Это история 3.
5. **Замеры.** SC-001…SC-003 на `mid`-сохранении; при промахе — порядок очереди и квота (R19).
