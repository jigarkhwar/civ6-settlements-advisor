# Ловушки игры

Нумерованный список ловушек Civilization VI, которые нужно соблюдать в коде мода.
Источники: разбор чужих модов (знания, пересказанные своими словами) и собственный опыт.
Новые ловушки добавляются в конец, номера не меняются.

| # | Ловушка | Как поступаем |
|---|---|---|
| 1 | Имя и описание мода в списке модов показываются из `<LocalizedText>` modinfo, пока мод выключен; тексты из файлов грузятся только во `FrontEndActions/UpdateText` | Дублируем имя, тизер и описание в modinfo и в `Text/*.xml`, подключаем тексты в `FrontEndActions` |
| 2 | Внешний XML с текстами принимает только формат `<GameData><LocalizedText><Replace Tag Language><Text>`; формат `<Text id><en_US>` работает только внутри modinfo, а во внешнем файле ломает загрузку | Внешние файлы — только `Replace` |
| 3 | Недопустимый атрибут в UI XML молча ломает контрол, в лог ничего не попадает | Сверяемся с примерами в `Base/Assets/UI`, проверяем `xmllint` |
| 4 | `PlayerConfiguration:GetMapPin(x, y)` на пустой клетке **создаёт** метку | Для поиска перебираем `GetMapPins()` |
| 5 | После создания новой метки ранее полученные объекты меток могут стать недействительными; обращение к ним роняет игру | Храним только ID метки и каждый раз берём объект заново |
| 6 | Скрытый контекст перестаёт получать `ContextPtr:SetUpdate`; вывод окна из очереди всплывающих окон скрывает контекст | Главный контекст мода не прячем и не ставим в очередь окон |
| 7 | Подключённый в своё состояние DMT подписывает свои обработчики (`DMT_Initialize`): 3 LuaEvents и 11 Events | Сразу снимаем их; кэш модификаторов строим сами (`InitializeModifierCalculator` один раз, `CacheEffectiveModifiers` при загрузке и в начале хода) |
| 8 | В Lua игры `string.gsub` с якорем `^` может заменить больше одного раза | Для изменения начала строки используем `sub` |
| 9 | Город забирает клетку, только если она примыкает к его территории; клетка в трёх кольцах, отрезанная чужой территорией, недостижима. Ни DMT, ни движок для неосвоенных клеток это не проверяют | Проверяем связность сами |
| 10 | В Gathering Storm затопленные прибрежные низины не принимают районы (`TerrainManager.IsFlooded`); DMT это не проверяет | Исключаем такие клетки сами |
| 11 | Слой `Hex_Coloring_Placement` рисует один и тот же зелёный при любом цвете | Красим слой `Hex_Coloring_Government` и перерисовываем его по `Events.LensLayerOn` |
| 12 | Имена таблиц и столбцов правил легко написать по памяти неправильно; ошибка всплывает только при обращении | Сверяем с `Cache/DebugGameplay.sqlite` (`pragma table_info`); выгрузка для тестов берёт имена из базы |
| 13 | Mac-версия не пишет `Lua.log` | Вывод Lua забираем через FireTuner (`tools/tuner.py`) |
| 14 | Игра обрезает пробелы по краям `<Text>` | Разделители с пробелами пишем внутри форматных строк |
| 15 | Lua 5.1 не умеет уступать управление (`coroutine.yield`) сквозь `pcall` | В фоновой работе не вызываем `SA_Scheduler.Tick` внутри `pcall` |
| 16 | Контекст из `AddUserInterfaces` (InGame) стартует скрытым (`ContextPtr:IsHidden()` = true): `SetUpdate` не вызывается, значки `WorldAnchor` не рисуются. Проверено в игре 2026-10-29 | В `LoadScreenClose` вызываем `ContextPtr:SetHide(false)` |
| 17 | Ошибка внутри обработчика `ContextPtr:SetUpdate` снимает его насовсем; на Mac её не видно (нет Lua.log) | Всё, что не в планировщике, вызываем из `OnUpdate` через `pcall` и печатаем `SA_ERROR` |
| 18 | Горячая перезагрузка контекста, пока Поселенец выделен и подсказка вызывает функцию мода, уронила игру (2026-10-29, `__cxa_pure_virtual` в потоке TBB). Новые файлы в `ImportFiles` и новые тексты горячая перезагрузка всё равно не подхватывает | В `SetShutdown`: `Shared.GetLines = nil`, `ClearUpdate`, `DestroyInstances`. После правки modinfo, текстов или списка файлов — перезагрузить сохранение, а не ждать горячей перезагрузки; перед горячей перезагрузкой снимать выделение с Поселенца |
| 19 | Игра падала (`__cxa_pure_virtual` в потоке TBB, 2026-10-29 08:48 и 09:01), пока значки обрабатываемых клеток (якоря `WorldAnchor` с текстом со значками доходов) пересоздавались при каждом движении курсора | Значки меняются только там, где меняется набор клеток; текст пишется только в новый значок; выключатель `SA_ShowWork` для проверки. Проверено 2026-10-29: без значков и с новой версией по 3–5 мин — без сбоя |
| 20 | Подсказка клетки узкая (`WrapWidth=200` в `PlotToolTip.xml`); строки, дописанные в конец, уходят за край экрана и их не замечают | Свой блок — первым; `SetWrapWidth(420)` пока выделен Поселенец, иначе 200 |
| 21 | Новый файл в `ImportFiles` (или другое изменение modinfo) не подхватывается загрузкой сохранения: список файлов мода игра читает из `Mods.sqlite` при запуске. Тексты при этом перечитываются | После правки modinfo — полный перезапуск игры. Проверка: `type(SA_DMT)` в `SA_Main` через Tuner |
| 22 | Горячая перезагрузка контекста мода уронила игру ещё раз (2026-10-29 11:16, тот же `__cxa_pure_virtual` в TBB), несмотря на защиту из ловушки 18: на карте были значки районов и метки | **Не править файлы мода при запущенной игре.** Порядок: быстрое сохранение (`OnQuickSaveGame` в `InGameTopOptionsMenu`) → выход (`OnExitGame`) → правки → запуск → `OnResumeGame` в `MainMenu` |

Подозрение — частые `ClearLayerHexes`/`SetLayerHexesColoredArea` и пересоздание якорей, пока движок их рисует | Линза перекрашивается только при изменении цветов; номера и сообщение — только при изменении; полная перерисовка не чаще раза в 30 кадров; до `LoadScreenClose` мод ничего не рисует |
| 24 | `os.clock()` в игре на Mac идёт целыми секундами (проверено 2026-10-29: 388, 397…), а `UI.GetElapsedTime()` внутри одного кадра не меняется. Замер куска кода в кадре даёт 0 или 1000 мс — записи `SA_SLOW … 1000 ms` были ложными | Длительность кадра мерить разницей `UI.GetElapsedTime()` между вызовами `OnUpdate` и относить её к заданию прошлого кадра; `os.clock` для замеров не использовать |
