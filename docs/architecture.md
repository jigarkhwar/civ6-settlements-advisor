# Settlements Advisor — схема мода

Архитектура, версия 2 (2026-10-28). Следует конституции v2.0.0 (`.specify/memory/constitution.md`).
Основана на разборе Smart District Planner (SDP), Fully Automatic Map Tacks Planner (AMT)
и Detailed Map Tacks (DMT).

## 1. Цель и чем мод лучше

**Выделил Поселенца — сразу видишь лучшее место, раскладку районов и улучшений и путь туда.**
Совместимость с другими модами не цель; цель — самый точный и самый полный совет.

| # | Что делаем | Как у SDP / AMT |
|---|---|---|
| 1 | **Ответ при выборе Поселенца** без панелей и кнопок: теплокарта, лучшие места, полупрозрачный план вокруг лучшего | SDP: открыть панель, выставить районы, запустить расчёт. AMT мест городов не выбирает |
| 2 | **Ценность города — симуляция на 60–100 ходов**: рост, жильё, довольство, обрабатываемые клетки, очерёдность районов; ранние доходы весят больше | Сумма бонусов соседства и стоимости клеток |
| 3 | **Путь Поселенца**: ходы до места и опасность по дороге входят в балл | Ни у кого |
| 4 | **Районы, улучшения и чудеса планируются вместе** (шахты и карьеры для Промзоны, фермы друг для друга в GS) | SDP улучшения не планирует; AMT — эвристикой |
| 5 | **Доказанный оптимум раскладки** (ветви и границы) или оценка разрыва до него | SDP: перебор только для малых случаев; AMT: beam search без гарантии |
| 6 | **Учёт всей империи**: перекрытие клеток, районы с радиусом, лояльность, торговые пути | SDP частично (несколько городов); AMT до 4 городов |
| 7 | **Неоткрытые клетки — ожидаемая ценность** по правилам генерации карты, с диапазоном | Исключаются |
| 8 | **Исправленный DMT** + сверка с движком: каналы, неубираемые ресурсы, затопленные низины, затонувшие корабли | Ошибки DMT наследуются (у AMT — жалобы на каналы) |
| 9 | **Веса по цивилизации и лидеру** предлагаются автоматически | SDP: шаблон районов по правилам; AMT: фокус дохода вручную |
| 10 | **План ведёт по игре**: метки после основания, Строитель, производство, пересчёт после технологий | Метки ставятся один раз |
| 11 | **Точность измерена**: калибровка по игре и бенчмарк против SDP и AMT | Не публикуется |
| 12 | **Русский язык** | Ни у кого |

Честная игра: только видимое игроку, скрытые ресурсы не читаются (принцип IX).

## 2. DMT

Мод зависит от DMT и берёт из него соседство и законность районов.

- Модули DMT подключаются в Lua-состояние мода (`include("dmt_yieldcalculator")`), подписки DMT
  в этом состоянии снимаются, кэш модификаторов строится самим модом.
- Для оценки гипотетических раскладок перехватываются `GetMapPinSubject`/`UpdateMapPinSubject`
  (свой слой воображаемых меток с воображаемым центром города; идея подсмотрена у SDP,
  улучшения — в `specs/001-settler-site-lens/research.md` R20).
- Код других модов, кроме подключения DMT, не используется (конституция, принцип X).
- Ошибки DMT исправляются обёртками; где движок даёт ответ (`CityManager.GetOperationTargets`),
  он главнее DMT.
- Файлы DMT не копируются: лицензии нет
  ([hanweizhang/Civ6DetailedMapTacks](https://github.com/hanweizhang/Civ6DetailedMapTacks),
  обновлён 2024-01-17). Исправления — в `docs/dmt-patches.md` и как PR автору.
- Бонусы цивилизаций через модификаторы DMT уже поддерживает.

## 3. Структура мода

```
SettlementsAdvisor/
├─ SettlementsAdvisor.modinfo
│    FrontEndActions: UpdateText, UpdateDatabase (горячие клавиши)
│    InGameActions:   UpdateText, ImportFiles (Scripts/*), AddUserInterfaces (UI/SA_Main),
│                     ReplaceUIScript (подсказка клетки, линзы — по мере необходимости)
├─ Config/SA_Input.xml
├─ Text/SA_Text_{en_US,ru_RU}.xml
├─ UI/
│   ├─ SA_Main.xml / .lua        контекст InGame: события выбора юнита, хода, видимости;
│   │                            запускает фоновые задачи, рисует линзу и предпросмотр
│   ├─ SA_PlotToolTip.lua        замена PlotToolTip поверх Expansion2: строки мода в подсказке клетки
│   └─ SA_Panel.xml / .lua       настройки весов, список мест, кнопка «план в метки»
└─ Scripts/                      чистая логика (принцип VI)
    ├─ SA_Rules.lua       всё из GameInfo/GlobalParameters
    ├─ SA_World.lua       снимок карты и империи; грязные участки по событиям; единственный доступ к игре
    ├─ SA_Prior.lua       ожидаемая ценность неоткрытых клеток и невидимых ресурсов
    ├─ SA_Candidates.lua  где можно основать город, с причиной отказа
    ├─ SA_Coarse.lua      быстрая оценка всех кандидатов (клетки, вода, роскошь, стратегические)
    ├─ SA_DMT.lua         подключение DMT, слой воображаемых меток, обёртки-исправления, сверка с движком
    ├─ SA_Layout.lua      раскладка районов + улучшений + чудес: ветви и границы, доказанный оптимум
    ├─ SA_Sim.lua         симуляция города на H ходов: рост, жильё, довольство, клетки, стройка
    ├─ SA_Path.lua        путь Поселенца, ходы, опасность
    ├─ SA_Empire.lua      вклад в империю: перекрытия, радиусы районов, лояльность, торговля
    ├─ SA_Weights.lua     веса по цивилизации и лидеру, пресеты
    ├─ SA_Score.lua       итог места = Σ слагаемых, каждое {value, range, reasons}
    ├─ SA_Explain.lua     слагаемые → текст подсказки
    ├─ SA_Scheduler.lua   фоновые задачи по кадрам, приоритеты, бюджет в операциях
    ├─ SA_Plan.lua        план города: хранение, метки, переход после основания, пересчёт
    └─ SA_Pins.lua        метки: только ID, отмена, свои vs игрока
```

## 4. Конвейер расчёта

```
события игры ─► SA_World (грязные участки)
                    │
                    ▼
             SA_Scheduler (фон, по кадрам, приоритет: рядом с Поселенцами)
                    │
  ┌─────────────────┼──────────────────────────────────────────────┐
  ▼                 ▼                         ▼                    ▼
Уровень 1        Уровень 2                 Уровень 3            SA_Path
SA_Coarse        SA_Layout (DMT)           SA_Sim + SA_Empire   (для каждого
все кандидаты    top ~30 у каждого         top ~5               Поселенца)
                 Поселенца: районы,        симуляция H ходов,
                 улучшения, чудеса         вклад в империю
  └─────────────────┴──────────────┬───────────────┴────────────────┘
                                   ▼
                              SA_Score ─► кэш результатов
                                   │
           выбор Поселенца ────────┼──────► линза + номера + предпросмотр плана
           наведение на клетку ────┼──────► подсказка (SA_Explain)
           город основан ──────────┴──────► SA_Plan → метки
```

Каждый уровень уточняет предыдущий; на экране всегда лучший уже готовый результат
(пометка «уточняется», пока выше уровни не досчитаны).

## 5. Модель оценки места

**Итог = ценность города за H ходов (дисконтированная) + вклад в империю − цена пути ± неопределённость.**

| Слагаемое | Что считаем | Источник |
|---|---|---|
| Рост и клетки | какие клетки обрабатываются при росте, с лучшими улучшениями по плану | SA_Sim, `Improvement_YieldChanges` |
| Жильё и довольство | вода, ферм-бонусы, роскошь; ограничивают рост в симуляции | `GlobalParameters`, `Resources.Happiness` |
| Районы | раскладка с доказанным оптимумом, очерёдность постройки, доход с момента постройки | SA_Layout + SA_DMT |
| Улучшения | бонусы улучшениям и от улучшений районам | SA_Layout |
| Роскошь и стратегические | новые виды, дефицит, эпоха | `Resource_Consumption` |
| Разовые доходы | вырубка и сбор | `Feature_Removes`, `Resource_Harvests` |
| Империя | перекрытие клеток с соседями, районы с радиусом, торговые пути | SA_Empire |
| Лояльность | давление в радиусе 9 по формулам игры | `CITIZEN_IDENTITY_PRESSURE_*` |
| Путь | ходы до места × потерянный доход за ход; опасность по дороге | SA_Path |
| Неизвестность | ожидаемая ценность неоткрытого + диапазон | SA_Prior |

Доходы умножаются на веса (SA_Weights), ранние ходы весят больше поздних (дисконт).
Горизонт H и дисконт калибруются (§7).

## 6. Интерфейс

1. **Выбор Поселенца:** линза мест (4 ступени цвета), номера 1–3, полупрозрачный план вокруг лучшего
   места (иконки районов, улучшений, чудес), путь до него с числом ходов.
2. **Наведение на клетку:** в стандартной подсказке — балл, слагаемые, диапазон, причина отказа;
   при наведении на кандидата план перерисовывается вокруг него.
3. **Кнопка «план в метки»** и автоматический переход плана в метки после основания города.
4. **Строитель:** подсветка клеток, где по плану нужны улучшения.
5. **Производство района:** подсветка его клетки по плану.
6. **Пересчёт** после технологий и цивиков, меняющих бонусы, с сообщением «план изменился» и разницей.
7. **Панель:** веса (по умолчанию от цивилизации), список мест, отмена меток.

## 7. Точность: калибровка и бенчмарк

- **Калибровка симуляции:** через FireTuner в автоматической партии основать город на месте,
  прогнать N ходов (`AutoplayManager`, как в SDP), сравнить фактические доходы с прогнозом SA_Sim.
  Ошибка — в `docs/accuracy.md`.
- **Бенчмарк:** на одинаковых сохранениях наш план против планов SDP и AMT: доход, доказан ли оптимум,
  время расчёта.
- **Решатель:** на малых случаях — сравнение с полным перебором; на больших — разрыв до верхней оценки.
- **Обёртки DMT:** тест, где без обёртки DMT ошибается, а с ней ответ совпадает с движком.

## 8. Тестирование и отладка

- **Автономно:** Lua 5.1 и свой поддельный мир (заглушки `GameInfo`, `Map`, `Plot`).
  Таблицы `GameInfo` выгружаются из `Cache/DebugGameplay.sqlite`.
- **В игре на macOS:** Mac-версия не пишет `Lua.log`, вывод только через FireTuner
  (свой клиент `tools/tuner.py`).
- **Детерминизм:** результат не зависит от порядка фонового расчёта; перебор по отсортированным массивам.

## 9. Известные ловушки игры (знания из разбора SDP, учитываем с первого дня)

- Имя мода в FrontEndActions, иначе в списке видно `LOC_…` (pitfall 1–2).
- Недопустимый атрибут в XML молча ломает контрол, ничего не попадает в лог (pitfall 8).
- `PlayerConfiguration:GetMapPin(x, y)` на пустой клетке **создаёт** метку (pitfall 22).
- Объект метки может стать недействительным после создания новой, обращение роняет игру — хранить только ID (pitfall 21).
- Скрытый контекст не получает `SetUpdate`, и фоновый расчёт останавливается (pitfall 23).
- Кэш модификаторов DMT в своём состоянии нужно строить самим (pitfall 25).
- В Lua игры `gsub` с якорем `^` заменяет больше одного раза (pitfall 39).
- Город может забрать клетку, только если она примыкает к его территории (pitfall 40).
- В Gathering Storm на затопленных низинах ничего строить нельзя (pitfall 41).
- `Plot:GetYield` в `GameCore_Tuner` не видит бонусов зданий; доходы читать в UI-состоянии (pitfall 34).
- Имена столбцов брать из `DebugGameplay.sqlite`, а не по памяти (pitfall 32).

## 11. Принятые решения (2026-10-28)

- Правила: только Gathering Storm.
- Языки: английский и русский.
- Совместимость с другими модами не цель; несовместимость с SDP и AMT принимается.
- DMT дорабатываем обёртками, файлы не копируем.
- Честная игра: скрытое не читаем, неизвестное — ожидаемой ценностью.
- Процесс: Spec Kit, принципы — в `.specify/memory/constitution.md` (v2.0.0).
- Первая версия (спецификация `specs/001-settler-site-lens`, уточнения от 2026-10-28):
  - номера 1–3 — три клетки с наибольшим баллом в радиусе 8 клеток от Поселенца, могут стоять рядом;
  - цвета — четверти баллов мест в радиусе 8 клеток от Поселенца;
  - районы — все специализированные районы цивилизации (кроме лимитированных на империю
    и невозможных по географии), мод сам решает про Акведук и Дамбу, оптимум общей пользы;
  - цены доходов: еда, производство, наука, культура 1; золото, вера 0,5;
  - улучшения клеток — лучшие за всю игру;
  - неоткрытые клетки — ожидаемая ценность по правилам генерации карты уже в этапе 1;
  - дополнительно (2026-10-28): достаточность еды для населения, риск затопления низин 1–3 м,
    разница с местом № 1 в подсказке, отметки обрабатываемых клеток; для разработки — тесты на
    снимках реальных карт и автосбор расхождений DMT с движком.

## 12. Будущие идеи (не в первой версии)

Идеи сверх других модов, отложенные на следующие функции. Для каждой записано, что она даёт.

| # | Идея | Что даёт | Куда |
|---|---|---|---|
| 1 | Доход пойм с учётом наводнений (`RandomEvent_Yields`): поймы со временем растут, Дамба этот рост отключает | честное решение по Дамбе, точнее ценность речных мест | симуляция роста (этап 4) |
| 2 | Время до районов: дисконт по числу технологий и цивиков до открытия при текущем темпе науки и культуры | район «через 100 ходов» стоит меньше района «сейчас» | симуляция роста (этап 4) |
| 3 | Производство на постройку: бедное производство строит районы позже | ценность районов во времени | симуляция роста (этап 4) |
| 4 | Особые бонусы GS: геотермальные источники (довольство от Акведука), рифы, вулканическая почва | точнее доходы и решение по Акведуку | этап 5 |
| 5 | Сравнение двух мест с Shift: два списка слагаемых бок о бок | выбор между двумя конкретными местами | интерфейс, после первой версии |
| 6 | Палитра для дальтоников и номера ступеней на клетках | доступность | интерфейс |
| 7 | «Место оспаривается»: рядом чужой Поселенец или растущие чужие границы | риск не успеть занять | учёт империи (этап 7) |
| 8 | Карта потолков соседства: максимум бонуса на каждой клетке для любого района, один раз на карту | мгновенная верхняя граница для любого места без DMT | ускорение, если SC-003 не выполнится |
| 9 | Повторное использование доказательства: изменение вне раскладки, не меняющее границу, не требует пересчёта | меньше пересчётов при открытии карты | ускорение |
| 10 | Самопроверка в игре: команда проверяет все инварианты на текущей карте | быстрый поиск ошибок у игроков | инструменты |
| 11 | Эталонные снимки подсказок на en и ru | любое изменение текста или чисел видно в тестах | тесты |
